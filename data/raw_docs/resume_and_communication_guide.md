# Campus Placement — Resume and Communication Skills Guide

## Resume Preparation for Technical Roles

A strong resume is the first filter in any placement process. This guide covers
best practices for engineering students applying to NovaTech, Meridian FinTech,
Aether Robotics, and similar technology companies.

## Resume Structure

### Contact Information
- Full name, personal email (professional-sounding address), mobile number.
- LinkedIn profile URL (optional but recommended).
- GitHub profile URL — mandatory if you have public code repositories.

### Education
- List your degree, institution, branch, CGPA, and expected or actual graduation year.
- Include only undergraduate (and postgraduate if applicable) details; omit 10th and
  12th board results unless they are exceptional or the company explicitly asks for them.

### Skills
List technical skills in categories:
- **Programming Languages**: order by proficiency. Be honest — if you list Java, expect
  Java questions.
- **Frameworks and Libraries**: Spring Boot, React, Django, TensorFlow, ROS 2, etc.
- **Tools**: Git, Docker, PostgreSQL, Redis, Jupyter, etc.
- **Platforms**: Linux, AWS (basic), Kubernetes (basic), etc.

Avoid listing every technology you have ever touched. A short, credible skills section
beats a long, unverifiable one.

### Projects
This section carries the most weight for campus candidates who lack work experience.
For each project:

**Format**:
```
Project Title | Technology Stack | Link (GitHub or live URL)
One-sentence description of what the project does and for whom.
• Bullet 1: what you built (be specific about the component you owned).
• Bullet 2: quantifiable outcome if available (e.g., "Reduced API latency by 35 %
  by introducing Redis caching").
• Bullet 3: a technical challenge you solved.
```

List 2–3 projects maximum. Quality beats quantity. A deeply understood project with
one interesting technical decision is more valuable than three superficial ones.

### Internship Experience
List in reverse chronological order. Include:
- Company name, role title, duration (month and year).
- Two or three bullet points on what you worked on and what you learned.
- At least one technical detail (language, framework, or system).

### Achievements and Certifications
- Competitive programming ratings (Codeforces, CodeChef, LeetCode) if noteworthy.
- Relevant certifications (AWS Cloud Practitioner, Google Associate Cloud Engineer,
  etc.) — list only if current and relevant to the role.
- Academic awards, scholarships, or research publications.

## Resume Common Mistakes

1. **Vague bullet points**: "Worked on backend development" conveys nothing.
   Write "Implemented a RESTful API in Spring Boot for user authentication, handling
   10,000 requests per day."

2. **Listing outdated or unverifiable skills**: claiming AWS expertise with no projects
   or certifications to back it up will be called out.

3. **Inconsistent formatting**: ensure font, bullet style, and spacing are consistent
   throughout. Use a single-column layout for ATS compatibility.

4. **Spelling and grammar errors**: run spellcheck and have a peer review your resume
   before submission.

5. **Exceeding one page**: for students with less than one year of work experience,
   a one-page resume is expected. Two pages is acceptable only for candidates with
   substantial internship or research experience.

## Communication Skills in Interviews

### Structured Verbal Responses

Use the STAR method for behavioural questions:
- **Situation**: briefly describe the context.
- **Task**: what was your specific responsibility?
- **Action**: what steps did you take? (This should be the longest part.)
- **Result**: what was the measurable outcome?

### Technical Communication

When answering technical questions:
1. **Clarify**: restate the question in your own words before answering.
2. **Structure**: say "I'll cover three aspects: first... second... third..." if the
   answer has multiple parts.
3. **Be precise**: use correct terminology. "The function runs in O(n log n) time
   because we sort the input" is better than "it's fast because of sorting."
4. **Acknowledge limits**: "I'm not certain about the exact implementation detail,
   but the principle is..." is better than guessing incorrectly with false confidence.

### Group Discussion (GD)

Some companies (NovaTech occasionally runs a GD round for batch hires) assess:
- Ability to make a clear, well-reasoned point.
- Active listening and responding to others' points.
- Not interrupting or dominating the discussion.
- Summarising the group's discussion if asked to close.

Topics at tech company GDs are typically current affairs with a technology angle
(e.g., "Should AI-generated code require mandatory attribution?") or case-study
scenarios (e.g., "Your startup's main competitor just launched a free version of
your product — what should you do?").

## Pre-Placement Talk Etiquette

Most companies hold a pre-placement talk (PPT) before the assessment. Attend it:
- Take notes on role descriptions, growth paths, and company culture — this material
  is directly useful in the HR round.
- Prepare 2–3 genuine questions to ask during the Q&A segment; asking no questions
  signals lack of interest.
- Dress professionally (business casual is appropriate unless formal dress is specified).
